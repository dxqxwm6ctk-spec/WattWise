# نسخة أونلاين على Railway (اختيارية)

> مهم: العرض قدام الحكام **ما بحتاج إنترنت ولا Railway**. العرض الأساسي بضل على اللابتوب:
> `python scripts/run_demo.py`. نسخة Railway بس عشان تفرجي حدا المشروع من أي مكان
> (زميل، مشرف، رابط بالـ proposal).

## شغّال لحاله بدون اللابتوب

- الرابط المباشر (السيرفر + اللوحة): https://wattwise-production-f321c49b.up.railway.app/index.html
  وصفحة الموبايل: `/app.html`.
- Railway مربوط بـ GitHub: كل ما ينرفع تعديل على `main`، Railway بيبني وبينشر **لحاله**. ما في داعي تفتح اللابتوب.
- تطبيق Flutter بيتصل بهاد الرابط تلقائياً. اللابتوب بس احتياط للعرض بدون إنترنت.

## شو اللي بصير على Railway؟

- إعدادات Railway موجودة بالملف `.railway/railway.py` (بدل `railway.json` القديم اللي Railway وقّف يقرأه بـ 1/12/2026)، وRailway بشغّل الأمر `python scripts/cloud_start.py`.
- إذا بدك تغيّر الإعدادات: `pip install railway-sdk`، عدّل الملف، بعدين `railway config plan` (بتشوف شو رح يتغيّر بدون ما يتغيّر شي) وبعدها `railway config apply`.
- هذا السكربت بشغّل السيرفر (FastAPI) على البورت اللي بعطيه Railway (`PORT`)،
  وبعدين بشغّل المحاكي (البيت + المبنى ١٠ غرف) عشان اللوحة يكون فيها بيانات **مصطنعة** حيّة.
- Railway بفحص `/api/health`، وإذا السيرفر وقع بعيد تشغيله.
- الريلاي الحقيقي والـ ESP32 **مش** موصولين بالنسخة الأونلاين. كل شي فيها محاكاة.

## الخطوات (مرة وحدة بس)

1. افتح https://railway.com واعمل حساب، والأسهل تدخل بـ **Login with GitHub**.
2. اضغط **New Project** ← **Deploy from GitHub repo**.
   إذا طلب صلاحية، اسمحله يشوف المستودع `WattWise` بس.
3. اختار `WattWise`. Railway رح يبلّش يبني لحاله (بشوف `requirements.txt`).
   البناء أول مرة بوخذ تقريباً ٣ لـ ٥ دقايق.
4. **خلّي قاعدة البيانات ما تنمسح** (منصوح فيه):
   - جوّا المشروع على Railway، كبسة يمين على الخدمة ← **Attach Volume** (أو من **+ Create** ← Volume).
   - خلّي الـ Mount path: `/data`
   - روح على الخدمة ← **Variables** ← **New Variable**:
     `WATTWISE_DB` = `/data/wattwise.db`
   بدون هاي الخطوة الموقع بشتغل عادي، بس البيانات بتنمسح كل ما يعيد النشر.
5. **اعمل رابط للموقع:** الخدمة ← **Settings** ← **Networking** ← **Generate Domain**.
   بطلعلك رابط مثل `https://wattwise-production-xxxx.up.railway.app`.
6. افتح الرابط وزيد عليه `/index.html`. لازم تشوف اللوحة والأرقام بتتحرك خلال ثواني.
   صفحة الموبايل: `/app.html`، والتقرير: `/api/sites/home/report`.

## متغيرات (Variables) اختيارية

| الاسم | القيمة | شو بعمل |
|---|---|---|
| `WATTWISE_DB` | `/data/wattwise.db` | مكان قاعدة البيانات على الـ Volume |
| `RUN_SIMULATOR` | `1` أو `0` | يشغّل المحاكي جنب السيرفر (الافتراضي `1`) |
| `SIM_SITES` | `home,building` | أي مواقع محاكاة تشتغل |
| `LLM_PROVIDER` | `none` | إذا بدك القواعد بس بدون ذكاء اصطناعي خارجي |

- **لا تحط `PORT` بإيدك**، Railway بحطه لحاله.
- مفتاح الـ LLM (`ANTHROPIC_API_KEY`) **مش لازم**. بدونه الوكيل بشتغل بالقواعد.
  إذا بدك تحطه، حطه بس بصفحة Variables على Railway، **وما تبعته بالشات لحدا ولا تحطه بالكود**.

## إذا صار مشكلة

- **البناء فشل (Build failed):** افتح **Deployments** ← آخر واحد ← **Build Logs**، وابعتلي آخر ٢٠ سطر (مش صورة للمفاتيح).
- **الموقع بقول Application failed to respond:** افتح **Deploy Logs**. لازم تشوف
  `WattWise backend is running on port ...` و`Simulators running`.
- **اللوحة فاضية:** استنى ١٠ ثواني وحدّث الصفحة، وتأكد إنه `RUN_SIMULATOR` مش `0`.

## ملاحظة أمان

الرابط عام: أي حدا معه الرابط بقدر يكبس موافقة/رفض على **المحاكاة**. هذا مش خطر لأنه ما في
أجهزة حقيقية موصولة، بس لا توصل الـ ESP32 والريلاي الحقيقي على النسخة الأونلاين.

## التكلفة

Railway فيه فترة تجربة مجانية وبعدها خطة مدفوعة صغيرة. المشروع خفيف (سيرفر واحد + SQLite).
تابع الاستهلاك من **Usage** بحسابك، وإذا خلصت المسابقة اعمل **Remove** للخدمة.
